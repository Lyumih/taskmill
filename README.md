# Taskmill

Taskmill — инструмент для организации работы над задачами в проекте. Он помогает сохранять проектный контекст и проходить подходящий workflow для разных типов задач. Инструмент рассчитан на индивидуальных разработчиков и команды.

## Ссылки

- [Веб-версия](https://taskmill-web.vercel.app/)
- [Репозиторий на GitHub](https://github.com/Lyumih/taskmill)

## Как это работает

1. Скилл или агент изучает проект и создаёт структурированное описание по согласованной схеме.
2. Локальный сервер читает это описание и предоставляет данные веб-интерфейсу.
3. Веб-интерфейс показывает контекст проекта, задачи и соответствующие процессы.

Файлы задач и конфигурации можно хранить в самом проекте или в отдельной папке, связанной с путём к основному проекту. CLI и MCP рассматриваются как дополнительные способы работы с теми же данными; MCP предназначен для подключения ИИ-клиентов.

## Модель workspace

- Плагин-блок — переиспользуемая реализация и схема содержимого в `apps/web/src/plugins/<plugin-id>`. Общие редакторы полей находятся в `apps/web/src/components`.
- Проект хранит доступность и значения плагинов, а также список процессов.
- Процесс задаёт тип задачи, этапы и упорядоченные ссылки на экземпляры плагинов.
- Задача хранит `processId` и переопределения значений отдельно для каждого процесса и экземпляра блока; пока переопределения нет, используется значение проекта.
- Task-блоки из legacy mock fixtures переносятся в `pluginData` при загрузке реестра; рабочий тип `TaskData` содержит plugin values, а не дублирует их отдельными секциями.
- Страница задачи позволяет выбрать процесс и заполнить его активные блоки; страницы блоков и процессов редактируют те же данные проекта.
- В текущем web-прототипе общий workspace хранится в памяти и сбрасывается при перезагрузке. Формат файлового хранения и сервер ещё не подключены.

## Направление развития

- Поддерживать разные workflow для новых возможностей, исправлений, исследований и других типов задач.
- Уточнять вопросы и шаги workflow по итогам выполнения задач.
- Сохранять описание проекта в переносимом, структурированном виде, который может читать локальный сервер.

## Технологии

- Веб-клиент: React, Ant Design, TanStack Query.
- Управление пакетами и приложениями: npm Workspaces.
- Сервер и формат описания проекта будут определены вместе со схемой данных.

## Первый этап

Согласовать постоянный формат описания проекта и задач на основе модели workspace, затем создать скилл или агента, который формирует документ. Локальный сервер сможет читать и сохранять этот формат, а веб-клиент — отображать и редактировать его содержимое.
