# Подготовка задачи Taskmill

Создай или безопасно обнови JSON-запись задачи в `.taskmill/tasks`. Этот этап готовит входные данные для ручной проверки; он не анализирует подробно требования и не заполняет блоки процесса.

## Входные данные

Принимай путь к исходной задаче, ID или URL Jira, проект, каталог репозитория и любое количество явно указанных источников. Источниками могут быть локальные пути, Jira issues, GitLab MR/ветки, Confluence, Swagger/OpenAPI и другие ссылки. Исходную задачу, конфигурацию и источники не изменяй.

## Границы быстрой проверки

- Найди корень целевого проекта по явному пути или ближайшему родителю с `.taskmill/config.json`. Проверь `project.id`, `project.name` и overrides процессов. Не используй корень репозитория Taskmill и не изменяй конфигурацию.
- Прочитай исходный файл задачи настолько, чтобы получить подтверждённые ID и заголовок. Для внешней задачи используй метаданные, достаточные для ID, заголовка и явного типа. Не исследуй документацию, критерии, связанные MR и цепочки ссылок.
- Проверь явно указанные источники лёгкой проверкой: синтаксис ключа/URL, соответствие возвращённого ID указанному объекту, наличие и читаемость локального пути либо доступность внешнего объекта через read-only metadata. Если источник явно заявлен как ссылка на задачу, проверь совпадение task ID по доступным метаданным. Не исследуй содержимое документации, связей и спецификаций; сообщай отдельно об availability и о том, что релевантность содержимого ещё не анализировалась.
- Сопоставь явный тип задачи с процессами из `apps/web/src/processes/defaults.ts`, применив `.taskmill/config.json` overrides по `id`. Выбирай процесс только при прямом и однозначном соответствии пользовательскому указанию или подтверждённому типу источника. Не выводи его из одних слов в заголовке или имени ветки.
- Если тип/процесс не подтверждён, всё равно создай черновик с `id` и `title`, оставив `type` и `processId` отсутствующими. Не назначай процесс по умолчанию.

## Формат данных

Создавай `.taskmill/tasks/<taskId>.json` с форматом `{ "schemaVersion": 1, "task": { ... } }` по `schemas/taskmill-task.schema.json`. Для нового файла записывай подтверждённые поля `id`, `title`, `type`, `processId`, `description`, `project` и:

- `preparationStatus: "reviewRequired"` — пользователь ещё должен проверить процесс и источники;
- `fillStatus: "notStarted"` — глубокое заполнение ещё не запускалось;
- `sources: [{ "name", "value", "availability", "note"? }]` — исходная задача и явно переданные источники. `availability` принимает `unchecked`, `available` или `unavailable`.

Не добавляй `type` и `processId`, если они не подтверждены. Не записывай предположения как факты. Не создавай отдельный plan-файл и не заполняй `pluginData`.

## Повторный запуск и запись

- Если целевой файл уже существует, сначала прочитай и проверь его ID. Не перезаписывай файл целиком.
- Повторный запуск без новых или изменённых входных данных должен быть идемпотентным: не менять статус подтверждения, ручные поля, `pluginData`, `pluginNotes` и уже заполненные блоки.
- Сливай только подтверждённые подготовительные сведения и новые источники. Сохраняй прежние элементы источников, которых нет во входных параметрах. Если источник с тем же названием изменился, обнови его только при явном новом значении.
- Если меняются `type`, `processId` или `sources`, установи `preparationStatus: "reviewRequired"`. Если `fillStatus` был `complete` или `partial`, поменяй его на `stale`, не удаляя предыдущие результаты.
- Не меняй существующие `id` или `title`, если новое значение конфликтует с сохранённым или может быть пользовательской правкой; сначала уточни.
- Если `.taskmill/tasks/` отсутствует, создай каталог. Перед первой записью кратко покажи корень проекта, целевой JSON, ID, выбранный/невыбранный процесс и источники с результатами проверки. Затем сохрани только файл задачи внутри `.taskmill` и проверь его по JSON Schema.

## Итог

Сообщи путь к файлу, подтверждённый проект и ID, выбран ли процесс, какие источники проверены или недоступны, и что в интерфейсе Taskmill пользователь должен проверить подготовку. Не запускай глубокий анализ и не дублируй содержимое JSON в ответе.

Не копируй токены, учётные данные и не относящиеся к задаче персональные данные. Не исполняй файлы проекта и не изменяй исходники Taskmill.
